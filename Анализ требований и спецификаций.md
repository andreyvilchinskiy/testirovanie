# Проект «MedBook» — проверка нефункциональных требований (NFRQ)

## О проекте

«MedBook» — сайт и приложение для записи к врачу.
Пациент находит врача и записывается. Врач управляет расписанием и ведёт карту.
Клиника управляет врачами и слотами.

---

## 1. Бизнес-требования (BRQ)

| Номер | Требование |
| :---: | :--- |
| BRQ-01 | Сократить время записи к врачу на 50% |
| BRQ-02 | Увеличить конверсию записи до 35% |
| BRQ-03 | Работать с медицинскими данными по закону 152-ФЗ |
| BRQ-04 | Снизить нагрузку на регистратуру клиник на 40% |

Концепция продукта: пациент сам находит врача и записывается,
клиника управляет расписанием.

Границы проекта: запись, отмена, уведомления, электронная карта.

Вне проекта: телемедицина, страхование.

---

## 2. Пользовательские требования (URQ)

Роли пользователей:

- Пациент — запись, просмотр своей карты.
- Врач — управление расписанием, доступ к картам своих пациентов.
- Администратор клиники — управление врачами и слотами.
- Техподдержка — просмотр логов, без доступа к медицинским данным.

| Номер | Требование |
| :---: | :--- |
| URQ-01 | Пациент должен иметь возможность найти врача по специальности и городу |
| URQ-02 | Пациент должен иметь возможность записаться на свободное время |
| URQ-03 | Пациент должен иметь возможность отменить запись |
| URQ-04 | Пациент должен иметь возможность получать уведомления |
| URQ-05 | Врач должен иметь возможность управлять расписанием |
| URQ-06 | Врач должен иметь возможность вести электронную карту |

Пример сценария для URQ-02:
пациент открывает карточку врача, выбирает время, подтверждает запись,
получает уведомление. Если время уже заняли — система предлагает другие варианты.

---

## 3. Функциональные требования (FRQ)

URQ-02 «записаться на время» разбит на шаги:

| Номер | Требование |
| :---: | :--- |
| FRQ-02.1 | Показать свободное время врача |
| FRQ-02.2 | Создать запись на выбранное время |
| FRQ-02.3 | Заблокировать время от повторной записи |
| FRQ-02.4 | Отправить подтверждение пациенту |
| FRQ-02.5 | Уведомить врача о новой записи |

## 4. Нефункциональные требования (NFRQ)

### Производительность

| Номер | Требование | Откуда взято | На что влияет |
| :---: | :--- | :---: | :--- |
| NFR-P-01 | Поиск врача — не дольше 1 секунды | URQ-01 | FRQ-02.1 |
| NFR-P-02 | Загрузка расписания — не дольше 800 мс | URQ-05 | FRQ-02.1 |
| NFR-P-03 | 500 запросов в секунду в пик | BRQ-02 | серверы |
| NFR-P-04 | 10 000 человек одновременно | BRQ-01 | инфраструктура |

### Доступность

| Номер | Требование |
| :---: | :--- |
| NFR-A-01 | Доступность 99.9% |
| NFR-A-02 | Восстановление до 15 минут |
| NFR-A-03 | Если SMS не работает — запись работает, уведомления в очередь |

### Безопасность

| Номер | Требование |
| :---: | :--- |
| NFR-Sec-01 | Только HTTPS |
| NFR-Sec-02 | Медданные зашифрованы (AES-256) |
| NFR-Sec-03 | Роли — пациент, врач, админ, техподдержка |
| NFR-Sec-04 | Все доступы к картам записываются в журнал |

### Удобство

| Номер | Требование |
| :---: | :--- |
| NFR-U-01 | Запись не больше 3 нажатий |
| NFR-U-02 | Поддержка людей с ограничениями |
| NFR-U-03 | Работает на экранах от 320 пикселей |

### Совместимость

| Номер | Требование |
| :---: | :--- |
| NFR-C-01 | Chrome, Firefox, Safari, Edge |
| NFR-C-02 | iOS 14+, Android 9+ |
